### 数字签名（Digital Signature）

- **用途**：用私钥对消息签名，用公钥验证签名是否有效。
- **输入**：算法（SM2 / RSA / ECDSA / Ed25519 / Ed448）、操作（签名 / 验签）、消息、私钥或公钥、签名值。
- **输出**：签名（Base64 编码的 ASN.1 DER）或验签结论 `valid`。
- **默认**：SM2 userId `1234567812345678`；RSA 摘要 `SHA256`、填充 `PSS`；SM2 摘要固定 `SM3`，ECDSA 固定 `SHA-256`。
- **安全提示**：签名与验签使用**不同的 userId** 会导致验签不通过；Ed25519 / Ed448 **不**支持自定义摘要，且消息**不得**预哈希。

**常见问题**

- **Q：验签显示 `valid: false` 是出错了吗？** A：不是，这是**业务结论** —— 消息被改动、密钥不配对或 userId 不一致都会导致该结果。
- **Q：SM2 签名能直接给 `openssl` 验吗？** A：可以，输出为 ASN.1 DER，与 OpenSSL 兼容。

### 非对称加解密（Asymmetric Encryption）

- **用途**：用公钥加密、用私钥解密，适合小数据与密钥交换。
- **输入**：算法（RSA / SM2）、操作、密钥、密文或明文。
- **输出**：密文。
- **默认**：SM2 输出 `C1C3C2` + `04` 前缀 + 裸格式；RSA 用 OAEP + SHA-256。
- **安全提示**：RSA 密文**长度受限**，大文件请改用对称加密。

**常见问题**

- **Q：SM2 密文能被 Java 库解开吗？** A：多数实现用 `C1C3C2`，与本工具默认一致；服务端也自动识别 DER 与 `C1C2C3` 输入。
- **Q：RSA 报「明文过长」怎么办？** A：RSA 只能加密极少量数据，请改用对称加密。

### 对称加解密（Symmetric Encryption）

- **用途**：用共享密钥加解密文本数据。
- **输入**：算法（SM4 / AES）、模式、填充、密钥、IV、附加数据、认证标签。
- **输出**：密文或明文，以及 GCM 认证标签。
- **默认**：填充 `pkcs7`；输出 `base64`；SM4 密钥 16 字节、AES 16 / 24 / 32 字节；GCM nonce 12 字节、tag 16 字节。
- **安全提示**：**不要**使用 ECB 模式；非 GCM 模式**没有**完整性校验，推荐 GCM。

**常见问题**

- **Q：GCM 解密报 `TAG_INVALID`？** A：tag 缺失、被截断，或密钥 / nonce / AAD 与加密时不一致。
- **Q：`padding: none` 报长度错误？** A：该模式要求输入是 16 字节的整数倍。
- **Q：为什么 AES 不能选 `zero` / `none` 填充？** A：底层库对 AES 静默忽略填充参数（恒用 PKCS#7），服务端因此显式拦截该组合，避免「加密按 PKCS#7、解密按 none」导致无法还原。

### ECDH 密钥协商（ECDH Key Agreement）

- **用途**：双方各自持有私钥，协商出同一份共享密钥。
- **输入**：曲线（P-256 / P-384 / P-521 / X25519 / X448）、本方私钥、对端公钥、可选 KDF 参数。
- **输出**：共享密钥与派生密钥。
- **默认**：KDF 为 HKDF-SHA-256；不做 KDF 派生时直接输出原始共享密钥。
- **安全提示**：共享密钥**必须**再经 KDF 派生后使用；**不要**把原始共享密钥直接当会话密钥。

**常见问题**

- **Q：为什么加了解码后双方结果不一致？** A：检查双方曲线是否相同、公钥是否被压缩或转换过。

### SM4 文件加解密（SM4 File Encryption）

- **用途**：对整个文件做分块加密，支持大文件。
- **输入**：操作（加密 / 解密）、模式（仅 GCM）、密钥、可选基础 nonce、可选分块大小、文件。
- **输出**：加密后文件（`.sm4` 容器）或解密后的原文件，以下载方式给出。
- **默认**：分块 1 MB；未提供基础 nonce 时随机生成。
- **安全提示**：密钥**不会**被保存，请自行保管；解密需要**完全相同**的密钥。
  文件在服务端流式处理，**不落盘**，也**不**写入日志与统计。

**常见问题**

- **Q：支持多大文件？** A：单次请求上限 100 MB。
- **Q：加密后的文件能直接用 `openssl` 解吗？** A：不能，本工具使用自定义容器格式 `TBFC`。
- **Q：解密时提示「密钥不对」怎么办？** A：确认密钥与加密时一致。容器逐块认证，被改动或被截断的内容都会被检测出来。
- **Q：上传的文件会被保存吗？** A：不会。文件在内存中流式处理，处理完即丢弃。

### HMAC 计算（HMAC Generator）

- **用途**：计算消息认证码，用于接口签名与完整性校验。
- **输入**：算法（HMAC-SM3 / HMAC-SHA256 / HMAC-SHA384 / HMAC-SHA512 / HMAC-SHA224 / HMAC-SHA1 / HMAC-MD5）、密钥、消息。
- **输出**：HMAC 值。
- **默认**：输出十六进制。
- **安全提示**：HMAC 密钥**不能**与服务端共享；HMAC-SHA1 / HMAC-MD5 **不**应用于安全场景。

**常见问题**

- **Q：算出来的值和对方不一致？** A：逐项核对：算法、密钥编码（hex 还是 utf8）、消息编码、大小写。

### 密码生成（Password Generator）

- **用途**：生成高强度随机密码与可发音口令。
- **输入**：长度、数量、字符集、是否排除易混字符、是否要求每类字符至少一个、策略模板、额外排除字符、口令单词数与分隔符。
- **输出**：密码列表、单密码的估算熵、实际套用的模板与字符池大小。
- **默认**：长度 16，数量 1，包含大小写 + 数字 + 符号，不使用策略模板。
- **安全提示**：本工具在**服务端**生成，密码**不**写入日志与统计；请用完后及时清理页面。

**策略模板**

| 模板 | 字符集 | 每类至少一个 |
| --- | --- | --- |
| 简单口令 | 小写 + 大写 + 数字 | 否 |
| 强口令 | 小写 + 大写 + 数字 + 符号 | 是 |
| 数字口令 | 数字 | 否 |
| 可发音口令 | 不使用字符池，由常见单词表拼装 | 不适用 |

> 模板只填充**未显式指定**的字段。可发音口令的强度取决于单词数，而非字符池；
> 此时界面给出的「估算熵」仍按字符池口径计算，**不应**作为强度依据。

**常见问题**

- **Q：熵值多少才够？** A：一般服务 ≥ 60 bit，重要账户 ≥ 80 bit。
- **Q：可发音口令怎么选单词数？** A：默认 3 个单词，配合分隔符与补足的数字；单词越多越难猜，也越难记。

### 摘要计算（Hash Calculator）

- **用途**：计算内容的校验和。
- **输入**：算法列表、内容。
- **输出**：各算法摘要与输入字节数。
- **默认**：输出十六进制。
- **安全提示**：摘要**不是**加密，无法还原原文；MD5 / SHA1 **不**应用于安全场景。

**常见问题**

- **Q：怎么校验下载文件完整性？** A：用相同算法分别计算本地文件与下载文件的摘要并比对。

### 密钥生成（Key Generator）

- **用途**：生成新的非对称密钥对。
- **输入**：算法、位数（RSA）、曲线（EC / SM2）、输出格式、是否用口令加密。
- **输出**：私钥 PEM、公钥 PEM。
- **默认**：RSA 2048 位；私钥 `PKCS#8`；公钥 `SPKI`；**不**加密。
- **限制**：`count` 当前只接受 `1`（响应结构只能表达一把密钥）；公钥只支持 `SPKI`。
- **安全提示**：私钥**只在响应中出现一次**，请立即保存；请用口令加密后再长期保存。

**常见问题**

- **Q：为什么私钥没口令也能下载？** A：默认不加密便于导入其它工具；长期保存**建议**加密。
- **Q：SM2 用哪种曲线？** A：选 `SM2`（对应 SM2 推荐参数），不是 P-256。

### 密钥格式转换（Key Format Converter）

- **用途**：在不同密钥格式之间转换。
- **输入**：密钥、源格式、目标格式、现有口令。
- **输出**：转换后的 PEM（`to: der` 时给出 base64 的 DER）与识别到的元信息。
- **默认**：源格式 `auto`（PEM → DER → base64 → hex 顺序识别）。
- **安全提示**：转换过程在服务端内存中完成，不落盘；加密私钥转换后**仍保持加密**。

**常见问题**

- **Q：`PKCS#1` 和 `PKCS#8` 有什么区别？** A：PKCS#1 是 RSA 专有格式；PKCS#8 是通用格式，**推荐**使用。
- **Q：能转成公钥格式吗？** A：私钥 → `SPKI` 不支持，请先提取公钥。

### 密钥解析（Key Parser）

- **用途**：查看密钥的算法、长度、曲线与参数。
- **输入**：密钥、口令。
- **输出**：算法、类型、格式、指纹、RSA 参数、规范化 PEM。
- **默认**：无。
- **安全提示**：解析**私钥**会显示敏感参数，请勿在共享屏幕下使用。

**常见问题**

- **Q：SHA-256 指纹是什么？** A：密钥公钥部分的哈希，可用于比对两把密钥是否相同。

### 密钥运算（Key Operations）

- **用途**：给私钥加解密、从中提取公钥、修改加密口令。
- **输入**：操作、密钥、口令、新口令。
- **输出**：操作后的 PEM。
- **默认**：PBE 算法 `AES-256-CBC`。
- **安全提示**：修改口令**不会**改变密钥本身，只是重新加密存储。

**常见问题**

- **Q：提取公钥需要口令吗？** A：不需要。

### 密钥配对检测（Key Pair Matcher）

- **用途**：判断私钥与公钥（或证书）是否属于同一对。
- **输入**：两段密钥材料。
- **输出**：是否匹配、结论说明、双方指纹。
- **默认**：无。
- **安全提示**：只比对公钥部分，**不**会泄露私钥。

**常见问题**

- **Q：能对比私钥和证书吗？** A：可以，服务端会提取证书的公钥再比对。

### JWK/XML 转换（JWK & XML Converter）

- **用途**：在 JWK（JSON Web Key）、PEM、XML（.NET `RSAKeyValue`）之间互转。
- **输入**：源格式与内容、目标格式、密钥类型。
- **输出**：转换结果。
- **默认**：私钥导出 JWK **必须**显式指定 `keyType: "private"`。
- **限制**：JWK 只支持 RSA 与 EC；XML 只支持 RSA。
- **安全提示**：导出私钥的 JWK **包含完整私钥材料**，等同于私钥本身。

**常见问题**

- **Q：JWK 里的 `kty` 是什么？** A：密钥类型，`RSA` 或 `EC`。

### 证书解析（Certificate Parser）

- **用途**：查看证书的颁发者、主体、有效期、扩展、指纹。
- **输入**：证书（PEM / DER / base64 / hex）、可选的判断时刻、可选的指纹算法列表。
- **输出**：证书详情、有效性状态、剩余天数、指纹、是否自签名。
- **默认**：按当前时间判断有效性；指纹**只**算 SHA-256。
- **安全提示**：只读工具，不修改任何材料。

**常见问题**

- **Q：怎样确认某张证书是否自签名？** A：`selfSigned` 为 `true`，且颁发者与主体一致。
- **Q：证书还没到生效时间怎么办？** A：会提示「尚未生效」，可传入 `atTime` 指定其它时刻判断。
- **Q：可以算 MD5 / SHA-1 指纹吗？** A：可以，工具支持 `MD5`、`SHA1`、`SHA256`、`SHA384`、`SHA512`、`SM3`；弱算法（MD5 / SHA-1）**不拒绝**，只附「弱哈希」警告。

### CSR 生成（CSR Generator）

- **用途**：生成提交给 CA 的证书签名请求。
- **输入**：证书类型、主体信息、密钥参数、SAN、用途扩展、挑战口令。
- **输出**：CSR PEM（及新生成的私钥）、自签名校验结果、指纹。
- **默认**：自动生成新密钥（RSA 2048）；私钥格式 PKCS#8；按证书类型预设密钥用途。
- **安全提示**：私钥**必须**自行安全保存 —— 丢失后只能重新生成。

**常见问题**

- **Q：CSR 里的 SAN 会被 CA 采纳吗？** A：多数 CA 会核对，**不要**在 CSR 里写与主体不符的域名。
- **Q：能复用已有私钥吗？** A：可以，传入 `existingPrivateKey`，此时响应**不**返回私钥。

### CSR 解析（CSR Parser）

- **用途**：查看 CSR 的主体、SAN、公钥与扩展。
- **输入**：CSR。
- **输出**：主体、SAN、公钥信息、签名算法、扩展、指纹、是否携带挑战口令、自签名是否校验通过。
- **默认**：无。
- **安全提示**：只读工具；挑战口令**只报存在性**，绝不回显口令值。

**常见问题**

- **Q：CSR 有有效期吗？** A：没有，但部分 CA 会限制重复提交频率。
- **Q：能知道 CSR 里有没有挑战口令吗？** A：只能知道**有**（`challengePasswordPresent`），口令值不回显。

### PEM/DER 转换（PEM & DER Converter）

- **用途**：在 PEM（文本）与 DER（二进制）之间转换。
- **输入**：内容与格式、目标格式、可选 PEM 标签、可选类型过滤。
- **输出**：转换结果、识别到的标签列表与块数。
- **默认**：输入格式自动识别；类型过滤为「全部」。
- **安全提示**：无。

**常见问题**

- **Q：PEM 头部的 `BEGIN` 后面是什么？** A：对象类型标识（`CERTIFICATE`、`PRIVATE KEY`、`PUBLIC KEY`、`CERTIFICATE REQUEST`…）。
- **Q：为什么转成 DER 只能给一个块？** A：DER 是单个对象的二进制编码，装不下多个 PEM 块。

### ASN.1 视图（ASN.1 Viewer）

- **用途**：把 DER 字节展开成结构树，便于排查证书问题。
- **输入**：DER / base64 / PEM。
- **输出**：长度、节点树、节点数与深度、十六进制转储。
- **默认**：最大深度 32（上限 64）。
- **安全提示**：无。

**常见问题**

- **Q：能看懂扩展里的 OID 吗？** A：可以，常见 OID 附中文说明。
- **Q：输入有大小限制吗？** A：有，请求体上限 **1 MB**；展开深度上限 64 层、节点数上限 10000。

### 证书链解析（Certificate Chain Parser）

- **用途**：把散乱的证书整理成正确顺序的链。
- **输入**：多个证书（拼接即可）。
- **输出**：排序后的链、是否已排序、是否缺根、是否自签名。
- **默认**：无。
- **安全提示**：无。

**常见问题**

- **Q：链应该按什么顺序？** A：叶证书 → 中间 CA → 根 CA。
- **Q：「是否已排序」为否是错误吗？** A：**不是**，它只表示输入需要重排；排序按 AKID ↔ SKID 匹配，同一层多个候选时按输入顺序取第一个。

### 证书链验证（Certificate Chain Verifier）

- **用途**：验证证书链是否可信、是否过期、是否匹配域名。
- **输入**：证书链、可选受信任根、可选验证时刻、可选主机名。
- **输出**：是否可信、错误列表、逐张证书的结论、域名匹配结果、是否使用隐含信任锚。
- **默认**：**没有系统信任根可用** —— 未传入受信任根时，把链内的自签名根当作**隐含信任锚**，此时「可信」**只**说明链内自洽。
- **安全提示**：验证失败**不是**错误，返回 `valid: false` 与原因列表。

**常见问题**

- **Q：自签名证书能通过验证吗？** A：若把该证书加入受信任根列表，则可以通过；否则只能用隐含信任锚。
- **Q：如何验证内网私有 CA 的证书？** A：把 CA 证书作为 `trustedRoots` 传入。
- **Q：域名匹配会影响链的可信判定吗？** A：**不会**，它只比对名字，结果单独给出。

### 证书链修复（Certificate Chain Repairer）

- **用途**：补全缺失的中间证书。
- **输入**：叶证书、可选中间证书集合、可选受信任根。
- **输出**：补全后的链、补充数量与来源、是否到达根。
- **默认**：无。
- **安全提示**：只做**本地**匹配与排序，**不**联网下载。

**常见问题**

- **Q：能自动从网上下载缺失的中间证书吗？** A：不能，本工具纯本地；请用 [证书链获取](#证书链获取certificate-chain-fetcher) 或手工补充。
- **Q：中间证书要放哪里？** A：填入「中间证书」输入框；工具先从中间证书里挑，再从受信任根里挑。

### 吊销状态检查（Revocation Checker）

- **用途**：用 CRL 判断证书是否已被吊销。
- **输入**：证书、CRL、可选的签发者证书。
- **输出**：`good` / `revoked` / `unknown` / `unverified`、CRL 编号与时间窗。
- **默认**：未提供签发者证书时不验签，只报 `unverified`。
- **安全提示**：需要提供 CRL 文件，**不**联网获取；过期的 CRL 一律拒绝。

**常见问题**

- **Q：`unknown` 是什么意思？** A：CRL 中没有该证书的记录 —— 可能是**未吊销**，也可能是 CRL 不完整。

### CRL 解析（CRL Parser）

- **用途**：查看吊销列表中的条目。
- **输入**：CRL。
- **输出**：签发者、有效期、签名算法、CRL 编号、被吊销条目列表。
- **默认**：无。
- **安全提示**：无。

**常见问题**

- **Q：吊销原因码怎么看？** A：`reasonCode` 是 RFC 5280 定义的数字，工具同时给出中文说明。
- **Q：序列号为什么可能是空的？** A：序列号超过 64 位时无法用整数承载，工具**不**输出错误值而留空（见 [上游缺口登记](upstream/tongsuo-go-issues.md)）。

### CRL 生成（CRL Generator）

- **用途**：用 CA 证书与私钥签发吊销列表。
- **输入**：签发者证书与私钥、待吊销证书、原因码、下次更新时间。
- **输出**：CRL 的 PEM 与 DER、编号、时间窗、吊销条目数。
- **默认**：编号自动生成；`thisUpdate` 取当前时间。
- **安全提示**：CRL 私钥等同 CA 私钥，请妥善保管。

**常见问题**

- **Q：CRL 有效期怎么设？** A：按业务需要设置 `nextUpdate`，过长会导致吊销信息延迟生效。

### OCSP 请求生成（OCSP Request Builder）

- **用途**：生成发给 OCSP 响应方的请求数据。
- **输入**：证书、签发者证书、哈希算法（SHA-1 / SHA-256 / SM3）。
- **输出**：DER 编码的请求（base64 与 hex）与字节长度。
- **默认**：哈希 `SHA256`。
- **安全提示**：无。

**常见问题**

- **Q：哈希能用 SHA-256 吗？** A：可以，但部分 OCSP 服务端只支持 SHA-1。

### OCSP 响应解析（OCSP Response Parser）

- **用途**：查看 OCSP 响应中的证书状态。
- **输入**：OCSP 响应、证书、签发者证书、可选的信任根。
- **输出**：响应级状态、证书状态、时间信息、响应者证书数、是否已验证签名。
- **默认**：未提供信任根时**不**验签（结果只解读内容）。
- **安全提示**：解析**不**等于验证响应者身份；要让「已验签」成立，必须提供信任根。

**常见问题**

- **Q：为什么状态是 `unknown`？** A：OCSP 响应本身不包含该证书的状态。

### 证书生成（Certificate Generator）

- **用途**：自签证书，或用 CA 证书签发子证书。
- **输入**：签发模式、签发者证书与私钥（或 CSR / 模板）、主体信息、密钥、SAN、用途、有效期。
- **输出**：证书 PEM、私钥 PEM（若新生成）、完整链、序列号与有效期。
- **默认**：随机序列号；有效期 365 天；签名算法按密钥类型自动选择；SKID / AKID 自动补齐。
- **安全提示**：**不要**用本工具签发的证书直接用于生产环境 —— 请用正式 CA。
- **限制**：`templateCert` 只复用公钥与有效期，**不**拷贝扩展（上游缺口 I-19）。

**常见问题**

- **Q：自签名证书和 CA 签发有什么区别？** A：自签名是**自己**签自己，浏览器不信任；CA 签发需要上级 CA 的证书与私钥。
- **Q：怎么延长有效期？** A：调整 `notAfterDays` 或直接指定 `notAfter`。

### PKCS#12 打包（PKCS#12 Packer）

- **用途**：把证书、私钥与链打包成 `.pfx` / `.p12`。
- **输入**：证书、私钥（**必填且须与证书配对**）、CA 链（可选）、口令、友好名称。
- **输出**：PKCS#12 内容（base64）。
- **默认**：口令为空即不加密（会附提示警告）。
- **安全提示**：PKCS#12 **必须**设口令；空口令的 `.pfx` 极不安全。

**常见问题**

- **Q：`.pfx` 和 `.p12` 是同一个东西吗？** A：是，PKCS#12 的两种常见扩展名。

### PKCS#12 解析（PKCS#12 Parser）

- **用途**：读取 `.pfx` 中的证书、链与私钥。
- **输入**：PKCS#12 内容（base64 / hex 自动识别）、口令。
- **输出**：主证书、CA 链、私钥 PEM。
- **默认**：无。
- **安全提示**：口令**不会**被记录；结果**包含私钥**，请确认环境可信。

**常见问题**

- **Q：报 `PASSPHRASE_INCORRECT`？** A：口令错误，或该文件使用了不支持的加密算法。

### PKCS#12 改密（PKCS#12 Password Changer）

- **用途**：修改 `.pfx` 的访问口令。
- **输入**：PKCS#12、原口令、新口令。
- **输出**：改密后的内容（base64）。
- **默认**：无。
- **安全提示**：请在安全环境中操作，避免原文件与结果同时留存。
- **限制**：**只**支持本工具打包的容器；外部工具产出的容器无法改密（上游缺口 I-22）。

**常见问题**

- **Q：改密后还能用吗？** A：可以，内容与证书链不变，只是加密口令变了。

### PKCS#7 打包（PKCS#7 Packer）

- **用途**：把证书链打包为 `.p7b`（DER 编码的 PKCS#7）。
- **输入**：证书（可多张，上限 64）。
- **输出**：PKCS#7 的 PEM 与 DER（base64）、证书数。
- **默认**：无。
- **安全提示**：PKCS#7 **不**包含私钥，**不**需要口令。
- **限制**：**只**做证书袋；签名 / 加密容器不在本版范围（上游缺口 I-11）。

**常见问题**

- **Q：`.p7b` 能直接上传到服务器吗？** A：多数服务器需要的是 PEM 拼接，请用 [证书链解析](#证书链解析certificate-chain-parser) 导出。

### PKCS#7 提取（PKCS#7 Extractor）

- **用途**：从 `.p7b` 中取出证书。
- **输入**：PKCS#7（PEM / DER / base64 / hex 自动识别）。
- **输出**：证书 PEM 列表与数量。
- **默认**：无。
- **安全提示**：无。

**常见问题**

- **Q：提取出来是乱码？** A：先确认文件确实是 PKCS#7 而不是 PKCS#12。

### CAA 生成（CAA Generator）

- **用途**：生成限制证书颁发机构的 DNS 记录。
- **输入**：域名、CAA 记录（标签 + 值）、可选 TTL。
- **输出**：逐条记录与可直接粘贴的区域文件行。
- **默认**：TTL 3600（填 0 则输出不带 TTL 的行）。
- **安全提示**：CAA 只影响**公网** CA 签发，私有 CA 不受影响。

**常见问题**

- **Q：CAA 写错会怎样？** A：会导致所有公网 CA **无法**签发该域名证书 —— 修改前请确认。

### 证书链获取（Certificate Chain Fetcher）

- **用途**：从运行中的服务器抓取它实际发送的证书链。
- **输入**：主机、端口、SNI。
- **输出**：完整链 PEM 与摘要（主体、签发者、有效期、链验证结论）。
- **默认**：端口 443，超时 30 秒。
- **安全提示**：本工具会**主动连接**目标服务器；内网地址与非白名单端口会被安全策略拦截。
- **限制**：只呈现服务端**实际发送**的证书，工具**不**补链。

**常见问题**

- **Q：抓到的链不完整？** A：服务器配置本身可能没发全中间证书，工具只是如实呈现。

### 证书透明度查询（Certificate Transparency Search）

- **用途**：在 CT 日志中查询某个域名签发过的证书。
- **输入**：域名、匹配方式、数量上限。
- **输出**：证书摘要列表。
- **默认**：精确匹配，最多 20 条。
- **安全提示**：CT 日志是**公开**数据。
- **限制**：**本版未实现**，调用返回 `NOT_IMPLEMENTED`（公开 CT 查询服务无稳定 SLA）。

**常见问题**

- **Q：为什么查不到某些证书？** A：私有 CA 签发的证书**不**进入 CT 日志。

### 域名验证（Domain Verifier）

- **用途**：验证域名所有权（DNS TXT / CNAME / 站点文件）。
- **输入**：验证方式、域名、期望值、可选解析器。
- **输出**：是否匹配、逐解析器结果、HTTP 状态与响应预览。
- **默认**：超时 5 秒。
- **安全提示**：本工具会**主动访问**你的验证地址；文件方式固定请求 `https://<domain>/<filePath>`，
  只有 `200` 且内容一致才算匹配。

**常见问题**

- **Q：DNS 已生效但仍不匹配？** A：检查是否有多条记录、TTL 是否未过期、期望值是否多了引号。

### Base64 编解码（Base64 Codec）

- **用途**：Base64 编码与解码，支持标准与 URL 安全变体。
- **输入**：操作、内容与输入编码、变体、填充选项。
- **输出**：结果。
- **默认**：标准变体、保留 `=` 填充。
- **安全提示**：Base64 **不是**加密。

**常见问题**

- **Q：解码报错？** A：确认输入编码（utf8 / hex）与变体是否选对；含换行不影响解码。

### URL 编解码（URL Codec）

- **用途**：URL 编码 / 解码，以及解析 URL 结构。
- **输入**：操作、内容、作用组件、是否把 `+` 视为空格。
- **输出**：结果；解析时给出各组成部分。
- **默认**：整体编码，`+` 视为空格。
- **安全提示**：无。

**常见问题**

- **Q：编码后 `:` 和 `/` 没被转义？** A：整串编码会保留 URL 保留字符，可改用「路径」或「查询」组件模式。

### JWT 编解码（JWT Codec）

- **用途**：查看 JWT 的头部与载荷，生成 HS 系列令牌，并校验 HS / RS / PS / ES256 签名。
- **输入**：操作、令牌或头部载荷、HMAC 密钥或公钥、算法。
- **输出**：头部、载荷、签名；生成时返回完整令牌。
- **默认**：算法 `HS256`。
- **安全提示**：**解析不等于可信** —— 头部与载荷只是 Base64URL 编码；只有「校验签名」通过才代表令牌可信。

**常见问题**

- **Q：能验证 RS256 的令牌吗？** A：可以。校验支持 RS / PS 系列与 ES256，需提供公钥；**生成**仍只支持 HS 系列。
- **Q：为什么 ES384 不可用？** A：底层 ECDSA 摘要固定为 SHA-256，传入 `ES384` 会返回 `UNSUPPORTED_ALGORITHM`。
- **Q：令牌已过期？** A：会给出 `expired` 提示，这是**结论**不是错误。

### 进制转换（Number Base Converter）

- **用途**：2–36 进制之间的数字转换。
- **输入**：值、源进制、目标进制、是否加前缀。
- **输出**：转换结果。
- **默认**：无。
- **安全提示**：无。

**常见问题**

- **Q：支持大整数吗？** A：支持，不受 64 位限制。

### 编码转换（Encoding Converter）

- **用途**：在 UTF-8、GBK、Big5、Shift_JIS、UTF-16、Latin-1 等字符编码间转换。
- **输入**：内容、源编码、目标编码、是否写 BOM。
- **输出**：转换结果（base64）。
- **默认**：源编码需指定（或 `auto` 探测）。
- **安全提示**：无法转换的字节会替换为 `�`，**可能**造成数据损失。

**常见问题**

- **Q：中文变成乱码？** A：源编码选错，先试 `GBK`。

### GZip/Deflate（GZip & Deflate）

- **用途**：压缩与解压文本或文件。
- **输入**：操作、格式（gzip / deflate / raw）、内容或文件、压缩级别。
- **输出**：结果与压缩比。
- **默认**：格式 `gzip`，级别默认。
- **安全提示**：解压有输出上限保护，防止**解压炸弹**。

**常见问题**

- **Q：解压失败？** A：确认格式选择正确（`deflate` 与 `raw` 是两种不同的 zlib 变体）。

**常见问题**

- **安全提示**：纯查表，**不出网**。

**常见问题**

- **Q：401 和 403 有什么区别？** A：401 表示缺少有效认证凭据、需要重新认证；403 表示服务端理解请求但拒绝授权。
- **Q：关键字能查中文吗？** A：可以，同时匹配原因短语、中文说明与类别中文名。

### 设备请求头（Device Headers）

- **用途**：按平台生成一组常见客户端请求头，或反向解析 User-Agent 串。
- **输入**：模式（生成 / 解析）；生成模式可选平台、版本号与操作系统；自定义请求头每行一条，格式为 `名称: 值`。
- **输出**：**生成模式**为请求头表格（名称、取值，逐行可复制）与 UA 串卡片；**解析模式**为统计卡片（浏览器、浏览器版本、操作系统、系统版本、设备类型、渲染引擎、是否爬虫）。
- **默认**：Chrome 桌面版。
- **安全提示**：纯内置模板与解析，**不**联网查询 UA 数据库。

**常见问题**

- **Q：生成的请求头能绕过风控吗？** A：不能，它只是常见请求头的模板，用于调试与兼容性测试。
- **Q：UA 数据库会更新吗？** A：不会自动更新，数据是内置快照，随工具版本更新。

### IP 段展开（IP Range Expander）

- **用途**：在 CIDR 与起止地址之间互转，并可把网段逐地址展开。
- **输入**：模式（地址转 CIDR / CIDR 转地址 / 展开地址列表）；网段或起止地址；展开上限。
- **输出**：统计卡片（模式、地址总数、起止地址、网段数量、截断标记）与列表表格（网段或地址，逐条可复制）。
- **默认**：展开模式，上限 1024 条；超出上限即截断并标记。
- **安全提示**：纯计算，**不出网**。

**常见问题**

- **Q：支持 IPv6 吗？** A：当前只支持 IPv4。
- **Q：为什么展开结果会被截断？** A：地址数超过上限时会停止并标记，避免耗尽内存与响应体。

### PDF 签名校验（PDF Signature Verifier）

- **用途**：校验 PDF 上的数字签名是否有效。
- **输入**：PDF 文件、可选受信任根、是否检查吊销。
- **输出**：签名列表、签名者信息、证书链结论、文件信息。
- **默认**：不检查吊销状态。
- **安全提示**：默认**不**联网检查吊销。

**常见问题**

- **Q：显示 `valid: false` 是因为 PDF 被改过吗？** A：常见原因是签名后内容被修改，或签发者证书已过期 / 不受信任。
- **Q：支持哪些签名类型？** A：常见的 PKCS#7 / CMS 签名。

### Markdown 预览（Markdown Preview）

- **用途**：渲染 Markdown，生成目录树。
- **输入**：Markdown 源文、方言、是否允许内嵌 HTML、是否把单换行当作换行。
- **输出**：HTML、目录列表。
- **默认**：方言 `gfm`，**不允许**内嵌 HTML。
- **安全提示**：输出已做净化，但前端**仍应**在隔离容器中渲染。

**常见问题**

- **Q：为什么表格没渲染？** A：请使用 GFM 方言（默认）。
- **Q：为什么 `<script>` 不生效？** A：出于安全考虑被过滤。

### EML 邮件解析（EML Parser）

- **用途**：查看邮件头、正文与附件。
- **输入**：`.eml` 文本（`input.text`）；本版**不**支持文件上传。
- **输出**：头字段、正文部分、附件列表。
- **默认**：单附件上限 10 MB。
- **安全提示**：附件内容**不**做安全扫描，请勿随意打开。

**常见问题**

- **Q：附件为什么是空的？** A：超过大小上限时只返回元信息。
- **Q：中文标题乱码？** A：邮件头编码不规范，尝试用 [编码转换](#编码转换encoding-converter) 处理。
