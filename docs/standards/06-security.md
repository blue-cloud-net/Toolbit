# 安全规范

> 状态：Stable ｜ 适用版本：v0.7.0 ｜ 最后更新：2026-10-29

---

## 1. 威胁模型

本项目是**单机部署、无用户账号**的公开工具箱。主要风险：

| 风险 | 说明 |
| --- | --- |
| 资源耗尽 | 大输入 / 高频请求 / 昂贵算法打满 CPU 与内存 |
| SSRF | 在线探测类工具访问内网地址 |
| 跨站滥用 | 他人页面诱导浏览器调用本服务（可消耗服务端资源） |
| 信息泄露 | 日志 / 统计 / 响应中残留密钥或隐私数据 |
| 供应链 | 依赖与镜像被篡改 |
| 依赖漏洞 | Go / Node / OS 组件 CVE |

**非目标**：本项目**不**提供用户隔离、权限、审计追溯；**不**保存用户密钥。

---

## 2. 无账号原则

- **禁止**引入注册 / 登录 / 会话。
- 服务端**不持久化**任何用户提交的材料（除匿名统计计数）。
- 「收藏 / 最近使用」只存在浏览器 `localStorage`。
- 统计**禁止**记录请求体内容，只记录 slug 与计数。

---

## 3. 输入处理

**必须**

- 所有输入在进入业务逻辑**前**做长度与格式校验；
- JSON 解码**必须**严格模式（拒绝未知字段）；
- 请求体**必须**用 `http.MaxBytesReader` 限制；
- 文件上传**禁止**落盘，**必须**走内存或流式；
- 上传文件的**扩展名与 MIME 一律不信任**（本项目无需按类型处理，只按字节流处理）。

**禁止**

- 把用户输入直接拼进 shell 命令（本项目**无**命令执行入口）；
- 把用户输入直接拼进 SQL（**必须**用参数化查询）；
- 把用户输入直接拼进正则（`regexp.Compile` 对用户输入做 ReDoS 防护；JS 侧 `regex-tester` **必须**设超时并限制模式长度）；
- 用 `fmt.Sprintf` 拼 SQL。

## 4. 出网安全（SSRF）

涉及网络的工具：`dns-lookup` `dns-tester` `ssl-check` `cert-chain-fetch` `ct-search` `domain-verify` `websocket-test` `pdf-sign-verify`（可选）。

**必须**

- 目标主机**必须**先做 DNS 解析，解析结果**全部**校验；
- **禁止**访问私有 / 保留网段：

  | 范围 | 说明 |
  | --- | --- |
  | `127.0.0.0/8` | 环回 |
  | `10.0.0.0/8` | 私有 |
  | `172.16.0.0/12` | 私有 |
  | `192.168.0.0/16` | 私有 |
  | `169.254.0.0/16` | 链路本地 |
  | `::1/128` | 环回 v6 |
  | `fc00::/7` | ULA |
  | `fe80::/10` | 链路本地 v6 |
  | `0.0.0.0/8` | 未指定 |

- **必须**校验 IPv4-mapped IPv6（如 `::ffff:127.0.0.1`）；
- **必须**防 DNS rebinding：连接时使用**已校验**的 IP，而非再次解析；
- 重定向**必须**逐跳校验（最多 3 跳），**禁止**自动跟随到内网；
- 出网**必须**通过统一 `netguard` 组件，**禁止**在工具里直接 `http.Get`。

**禁止**

- 允许用户指定端口绕过限制（只允许 80 / 443 / 853 等白名单端口）；
- 允许 `file://`、`gopher://` 等非 HTTP(S) 协议；
- 关闭重定向校验。

### 4.1 实现口径（`backend/internal/netguard`）

| 项 | 取值 |
| --- | --- |
| 端口白名单 | `43`（whois）、`53`（自定义 DNS）、`80`（`domain-verify` 的 `http-file`）、`443`、`853`（DoT） |
| 重定向上限 | 3 跳 |
| 禁止网段 | 见 [../api/tools/network.md](../api/tools/network.md) 的「出网安全」表 |
| 放行机制 | `TOOLBIT_NETWORK_ALLOWLIST`（精确主机名或 `*.suffix`），命中后**仅**跳过私网校验 |
| 系统解析器 | `/etc/resolv.conf` 里的服务器属运维配置，**不**做私网校验；用户自定义的服务器仍要校验 |

- 字段层**只**校验端口范围（1–65535）；**白名单**由 `netguard` 在出网时裁决，
  不通过即 `SSRF_BLOCKED`。这样端口策略只有一处事实来源。
- `netguard.Config.ExtraPorts` **仅供测试**：不从环境变量读取，部署时无法放宽白名单。
- 出网探测**不**依赖握手期的链验证结论（否则拿不到无效证书的细节）；
  拿到链之后再单独验证，并在响应里区分 `chainValid` 与 `verified`。

## 5. 跨站请求防护

虽然本服务**不**依赖 Cookie，但攻击者可用受害者浏览器发起请求以消耗服务端资源。

**必须**

- 校验 `Origin` / `Sec-Fetch-Site`；
- 对**有副作用**（消耗资源）的请求要求 `Sec-Fetch-Site: same-origin` 或 `same-site`；
- 拒绝 `cross-site` → `403` + `CROSS_ORIGIN_BLOCKED`；
- **禁止**使用 CORS `Access-Control-Allow-Origin: *` 搭配 `Access-Control-Allow-Credentials: true`。

**建议**

- 支持 `TOOLBIT_ALLOWED_ORIGINS` 白名单（默认空 = 不启用 CORS）。

## 6. 限流

**必须**按 catalog 的 `rateClass` 施加限流。

| 层级 | 标识 | 目的 |
| --- | --- | --- |
| L0 静态 | 静态文件 | 弱化 |
| L1 轻量 | 编码 / 格式化 / 文本 | 常规 |
| L2 中等 | 摘要 / HMAC / 对称 | 常规 |
| L3 重 | 密钥生成 / 证书 / PKCS#12 | 保护 CPU |
| L4 昂贵 | 文件加解密 / 网络探测 | 保护网络与内存 |

- 限流以 **IP** 为键，**禁止**信任 `X-Forwarded-For` 除非显式配置可信代理；
- 超限**必须**返回 `429` + `Retry-After`；
- **必须**用 `Retry-After` 而不是自定义字段。

## 7. 密码学使用规范

详见 [03-crypto.md](03-crypto.md)。安全底线：

- **禁止**自己实现算法；
- **禁止**使用 ECB 做敏感数据加密；
- **必须**为 GCM 提供并校验 tag；
- **禁止**复用 GCM 的 `(key, nonce)`；
- **必须**校验 RSA 密钥长度 ≥ 2048（否则 `SMALL_RSA_KEY` 警告）；
- **禁止**把密钥材料放进日志、错误、panic；
- **必须**使用 CSPRNG；
- **必须**在口令派生中使用足够迭代（PBKDF2 ≥ 100k，scrypt N ≥ 2¹⁴，Argon2id 内存 ≥ 64 MB）。

---

## 8. 密钥与敏感数据处理

| 场景 | 规则 |
| --- | --- |
| 接收私钥 | 只在内存中处理，**禁止**落盘 |
| 生成私钥 | 可选下载为文件（用户主动行为），**禁止**自动落盘 |
| 加密私钥 | 口令派生参数**必须**随密文保存（头部或参数区） |
| 日志 | **禁止**记录密钥、口令、证书正文 |
| 错误 | **禁止**回显输入原文 |
| 统计 | **禁止**记录请求体 |
| 临时文件 | **禁止**创建（若不得不创建，`defer` 立即删除并设 0600） |

**必须**在 UI 上明确提示「本工具在浏览器侧/服务端处理，请勿输入生产密钥」类安全提示（catalog `sensitive: true` 决定是否展示）。

## 9. HTTP 安全响应头

**必须**设置：

| 头 | 值 |
| --- | --- |
| `X-Content-Type-Options` | `nosniff` |
| `X-Frame-Options` | `DENY` |
| `Referrer-Policy` | `no-referrer` |
| `Cross-Origin-Opener-Policy` | `same-origin` |
| `Cross-Origin-Resource-Policy` | `same-origin` |
| `Content-Security-Policy` | `default-src 'self'; ...`（见 [09-docs.md](09-docs.md) 或部署文档） |
| `Permissions-Policy` | 关闭不需要的浏览器能力 |
| `Cache-Control` | API 响应 `no-store` |

**禁止**为 API 响应设置 `Access-Control-Allow-Origin: *`。

## 10. 依赖与供应链

- Go 依赖**必须**用 `go.sum` 锁定，**禁止** `go get` 引入未锁定依赖。
- 前端依赖**必须**用 `pnpm-lock.yaml` 锁定。
- **必须**在 CI 运行 `govulncheck ./...` 与 `pnpm audit`。
- 镜像**必须**基于固定 digest 的基础镜像（**禁止**使用 `latest`）。
- 镜像**必须**以非 root 用户运行（UID 10001）。
- **必须**提供 `docker scout` / Trivy 扫描的 CI 步骤。
- 许可证**必须**兼容 Apache-2.0（**必须**在 CI 检查新增依赖许可证）。

---

## 11. 容器安全

- **必须**用 multi-stage 构建，运行时镜像**不含**编译工具链。
- **必须**只暴露 30234。
- **禁止**挂载宿主机敏感路径进容器。
- **禁止**在容器内以 root 运行服务进程。
- 写目录（数据卷）**必须**属主为 `10001:10001`。
- **必须**有 `.dockerignore`，排除 `.git`、`.env`、`node_modules`、`docs`、`testdata`。

---

## 12. 日志与隐私

- 日志**禁止**包含：请求体、响应体、密钥、口令、证书正文、原始 IP、User-Agent 原文。
- IP 若需记录，**必须**做截断或哈希（`/24` 截断或 SHA-256 前 8 字节）。
- 统计**禁止**记录请求体与参数内容。
- 保留期：应用日志 14 天，统计原始数据 90 天。

---

## 13. 错误与信息泄露

- **禁止**回显底层 C 库错误文本。
- **禁止**回显用户输入原文到错误消息。
- **禁止**在 500 响应中附带堆栈。
- **必须**用统一的 `INTERNAL_ERROR` + `requestId`，让用户可凭 `requestId` 向维护者报告。

---

## 14. 依赖升级流程

1. 打开 Renovate / Dependabot PR；
2. CI 全绿（含 `-race`、fuzz 短跑、契约测试）；
3. 人工复核 changelog 中的安全条目；
4. 合并前跑 `govulncheck` 与镜像扫描；
5. 记录到 [CHANGELOG.md](../../CHANGELOG.md)。

**禁止**在功能分支中夹带依赖升级（**必须**独立提交）。

---

## 15. 禁止清单

- ❌ 引入用户账号体系。
- ❌ 记录请求体或密钥到日志。
- ❌ 访问内网地址（除显式白名单）。
- ❌ 跟随重定向到内网。
- ❌ 使用 `Access-Control-Allow-Origin: *`。
- ❌ 信任未配置的 `X-Forwarded-For`。
- ❌ 自己实现密码算法。
- ❌ 使用明文口令存储。
- ❌ 以 root 运行容器内进程。
- ❌ 在代码中硬编码密钥或口令。
